# 見本: 章立ての「自動下書き」を捨てた

## 状況

合奏練習の録画は 3〜4 時間ある。曲を通した区間、指揮者が止めて話す区間、休憩が入り混じる。
ここに章を打たないと、後で「あの箇所」に戻れない。章立ては毎回、数時間かかる手作業だった。

## 最初にやったこと

音響特徴から区間を判別し、章立ての下書きを自動で吐く道具（`segments-detect --chapters`）を作った。
人はそれを直せばよい、という筋書きだった。

## 何が起きたか

確定済みの章立てと比べた一致率は **52.4%**。

半分しか合わない下書きは、どの境界も信用できない。結局、人は全部の境界を確かめ直すことになる。
**下書きは検証の手間を減らさず、削除と修正の手間だけを足した。**
もっともらしい誤った境界を、そのまま受け入れてしまう危険も加わった。

一方、スペクトログラムを見ながら一から打つと、**確かめることと作ることが同じ一つの動作**になる。
実測すると、一から作る方が速かった。

ついでに「確実な目印だけを打つ」案も、作る前に 10 分で測った。

- 長い無音を目印にすると、適合率は最良でも **22%**。3.7 時間に 126 個も出て、目印というより雑音だった。
- 曲の境目の直前 60 秒で、無音が続いた最長時間は **中央値 2 秒**。曲間は指揮者が話しているので、持続する無音がそもそも無い。

無音は境界に存在するが、境界に特有ではなかった。

## 今どうしているか

章は Chaptr でスペクトログラムを見ながら人が打つ。検出結果は章表に流し込まず、波形の上に「候補」として出すだけにした。

```
[◀候補] [候補▶] で候補へ飛ぶ → 前後に送って詰める → [確定]
```

確定に使う時刻は、候補の時刻ではなく **その時の再生位置**。送り戻しで詰めた位置こそが人の判断だからである。

休憩の判別も、実素材で試すまで採用しなかった。合成データでは 85% 合っていたのに、実際の 134 分の録画では、休憩を 12 個捏造していた。

確定した章立ては、次のように書いた 1 枚のテキストになる。これがパイプラインの凍結点で、下流はすべてここから作られる。

```
00:00:00 -- 開始前
00:14:09 001 Opening Tune
01:13:40 -- 休憩
```

## 一行で

下書きが役に立つのは「確かめる＋直す」が「一から作る」より安いときだけ。目印を出す前に、それが本当に目印になるかを測る。
